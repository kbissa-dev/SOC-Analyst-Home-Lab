# SOC Analyst Home Lab

A hands-on cybersecurity home lab focused on developing practical junior SOC analyst skills through Windows telemetry, Microsoft Sentinel, KQL, investigation, detection and incident-response exercises.

## Current Lab Pipeline

- Windows 10 target VM
- Azure Arc
- Azure Monitor Agent
- Data Collection Rule
- Log Analytics workspace
- Microsoft Sentinel
- `SecurityEvent` table
- KQL investigation

The pipeline has been verified using real Windows Security events generated by the lab endpoint and queried in Microsoft Sentinel.

## Investigations

### Investigation 001 - Windows Failed Logon Followed by Successful Logon

Investigated two failed Windows authentication events (Event ID 4625) followed by a successful authentication event (Event ID 4624).

The investigation examined the account, timestamps, logon type, failure status, source information and event sequence to determine whether the activity warranted escalation.

**Assessment:** Likely benign.

The original investigation was completed in Windows Event Viewer. A later Microsoft Sentinel follow-up verified that Windows Security telemetry was reaching the `SecurityEvent` table and reviewed authentication and group-membership events using KQL.

[View Investigation 001](investigations/001-windows-failed-logon/investigation.md)

### Investigation 002 - WMI-Spawned PowerShell Execution

Built and validated a Microsoft Sentinel scheduled analytics rule that detects Windows Event ID 4688 when `WmiPrvSE.exe` creates `powershell.exe`.

The investigation used an authorised Atomic Red Team test, correlated the activity using a unique GUID, and examined the process, parent process, command line and account context.

During validation, I identified duplicate incidents caused by overlapping query windows. I tuned the rule using `ingestion_time()` and confirmed the result with a second controlled test.

**Assessment:** Benign true positive.

**Validation result:** One Atomic execution produced one security event, one alert and one incident after tuning.

[View Investigation 002](investigations/002-wmi-spawned-powershell/investigation.md)

### Investigation 002A - Sentinel SOAR Triage and Containment Simulation

Extended Investigation 002 with Microsoft Sentinel automation. An automation rule tags new incidents and runs a triage playbook that checks the live incident and skips closed or already-triaged incidents. A separate playbook, started manually by the analyst, records a containment simulation without changing the incident's status, severity or owner.

Both playbooks use system-assigned managed identities with the Microsoft Sentinel Responder role, and duplicate runs are prevented with markers. I tested the open, closed, duplicate and forced-failure paths, and documented the limitations I could not verify.

**Validation result:** Each playbook comments once per incident, intentional skips end as Cancelled, and a forced failure triggered the Azure Monitor alert.

[View Investigation 002A](investigations/002a-sentinel-soar-automation/investigation.md)
